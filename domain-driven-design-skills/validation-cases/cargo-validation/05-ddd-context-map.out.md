# 05 — ผลลัพธ์ ddd-context-map (Blind Run)

> ข้อมูลนำเข้า: ผลลัพธ์ blind run จาก `01`~`04`
> ไฟล์นี้เป็นผลลัพธ์จากการจำลองการทำงานของ `ddd-context-map` ใน blind run โดย **ไม่ได้อ้างอิง** วัสดุ ground truth ใน `reference/` ใดๆ

## เมทริกซ์ความสัมพันธ์ระหว่าง Context

| ต้นน้ำ → ปลายน้ำ | รูปแบบความสัมพันธ์ | วิธีการเชื่อมต่อ | สัญญาการส่งข้อมูล | ทิศทาง |
| :--- | :--- | :--- | :--- | :--- |
| Handling → Booking | Customer-Supplier | Event แบบไม่พร้อมกัน ("ข้อเท็จจริงการปฏิบัติงานได้รับการยอมรับ") | Published Language: AcceptedHandlingEvent (order, handlingType, occurredAt, location, voyageLeg, version) | ทางเดียว (Handling ต้นน้ำ) |
| Booking → Tracking | Open Host Service + Published Language | การสมัครรับ Event แบบไม่พร้อมกัน | กลุ่ม Event TrackingProjection: ShipmentBooked / RouteAssigned / RouteReassigned / CargoMisroutedDetected / ETARecalculated / HandlingApplied | ทางเดียว (Booking ต้นน้ำ) |
| Booking → Pathfinder (ทิศทางเรียกใช้)<br>Pathfinder → Booking (ทิศทางจัดหาข้อมูล) | Customer-Supplier + ACL (ตรงข้ามกับ Conformist) | ร้องขอ/ตอบกลับแบบซิงโครนัส | OpenAPI ภายนอก → แปลงเป็น "ร่าง RouteCandidate / Leg / VoyageSchedule" ภายในผ่าน ACL | สองทิศทาง (Booking เรียกใช้ฝ่ายเดียว) |
| Handling → Tracking | ไม่มีความสัมพันธ์โดยตรง | — | ห้าม; ต้องผ่าน Booking เป็นตัวกลาง | — |

## การเป็นเจ้าของสัญญา

| สัญญา | เจ้าของ | กลยุทธ์การเปลี่ยนแปลง |
| :--- | :--- | :--- |
| AcceptedHandlingEvent (Handling เผยแพร่) | ทีม Handling | ให้ความสำคัญกับการเข้ากันได้ย้อนหลัง: เพิ่มฟิลด์ใหม่ได้; ลบ/เปลี่ยนชื่อต้องมีหมายเลขเวอร์ชันและเปิดตัวแบบ gradual |
| กลุ่ม Event ที่คำนวณของ Booking (ส่งให้ Tracking) | ทีม Booking | ดูแลในฐานะ Published Language ของ Open Host Service; การเปลี่ยนแปลงใช้กฎการเข้ากันได้ย้อนหลังเดียวกัน |
| รูปแบบร่าง RouteCandidate ภายใน | ทีม Booking (กำหนดผ่าน ACL) | ACL ดูดซับการเปลี่ยนแปลงจากภายนอก โมเดลภายในของ Booking ไม่เปลี่ยนแปลง |
| กฎการแปลง ACL | ทีม Booking + ผู้ดูแลการเชื่อมต่อ (ร่วมดูแล) | การเปลี่ยนแปลงอินเทอร์เฟซภายนอกทุกครั้งจะกระตุ้นการทดสอบ ACL แบบ regression |

## การตัดสินใจ ACL / การแปลง

### ACL-1: Pathfinder → Booking

- **ขาเข้า**: ตัวเลือกที่เป็นไปได้ภายนอก (ชื่อฟิลด์ หน่วย เขตเวลาอาจพัฒนาอิสระจากภายนอก)
- **ขาออก**: `RouteCandidate { origin, destination, legs[], estimatedArrival }` ภายใน
- **กฎ**:
  - รหัสท่าเรือภายนอกอาจเป็น 3 ตัวอักษรหรือรหัสที่กำหนดเอง → ACL แปลงเป็นรหัสท่าเรือภายในที่เป็นมาตรฐาน รหัสที่ไม่รู้จักเข้าสู่เขตกักกันและแจ้งเตือน
  - เวลาแปลงเป็น UTC + semantics ของ occurredAt เสมอ
  - ฟิลด์ที่เกี่ยวกับราคา **ละทิ้ง** (ไม่ใช่เป้าหมาย)
  - เวอร์ชันที่ไม่เข้ากัน: ACL ลดระดับเป็นตัวเลือกแคชของเวอร์ชันล่าสุดที่รู้จัก; ถ้าไม่มีก็ส่ง "รายการว่างแบบลดระดับ" กลับไป

### ACL-2: การปรับ "ภาษาท้องถิ่น" ทางเข้าของ Handling

- Handling แม้จะเป็น Context ภายใน แต่ช่องทางภายนอก (Web/API/ไฟล์) แตกต่างกันมาก ภายในสร้าง **ชั้นปรับช่องทาง** ก่อนเพื่อแปลง load หลายรูปแบบให้เป็น "คำสั่งลงทะเบียน" แบบมาตรฐานเดียว ก่อนเข้าสู่สายพาน idempotency และการตรวจสอบ
- ชั้นปรับนี้ไม่ใช่ ACL (ต่อภายในไม่ใช่ภายนอก) แต่ทำหน้าที่คล้ายกัน

## รูปแบบความล้มเหลวและการลดระดับ

| สถานการณ์ | ผลกระทบ | การจัดการ |
| :--- | :--- | :--- |
| Pathfinder timeout / 5xx | ขั้นตอนสั่งซื้อ: ไม่สามารถส่งตัวเลือกกลับได้ | ACL ส่ง "แคช + ลดระดับเป็นรายการว่าง"; ชั้นบนของ Booking ตั้ง `ShippingRequest` เป็น "รอทดลองใหม่ภายหลัง" ไม่สร้างคำสั่งซื้อ |
| Pathfinder ส่งค่าว่างกลับมา | ไม่มีตัวเลือกที่เป็นไปได้ | ส่ง Event `NoFeasibleOptions` ผลักดันให้ฝ่ายปฏิบัติการตรวจสอบ |
| Handling ต้นน้ำหยุดทำงาน | Booking ไม่สามารถคำนวณสถานะต่อได้ | Booking หยุดการอัปเดต ETA; มุมมอง Tracking แสดงป้าย "ข้อมูลล่าช้า" |
| Handling มาถึงเป็นชุด | สถานะในอดีตต้องคำนวณย้อนหลัง | Booking สมัครรับ `LateHandlingIngested` รันสายพานคำนวณใหม่ตาม occurredAt; มุมมอง Tracking อัปเดตแบบไม่พร้อมกัน |
| การเผยแพร่ Event ของ Booking ล้มเหลว | มุม-view Tracking ล้าหลัง | Event bus บันทึกถาวร + เล่นซ้ำ; ผู้บริโภค idempotent |
| ACL ไม่สามารถระบุฟิลด์ใหม่จากภายนอกได้ | ข้อมูลอาจสูญหาย | load ดิบเข้าสู่เขตกักกัน แจ้งเตือน; Booking ไม่ยอมรับความหมายที่ไม่รู้จัก |

## กลยุทธ์เวอร์ชันและการพัฒนา

- Event ทั้งหมดที่เผยแพร่ภายนอกใช้ **หมายเลขเวอร์ชันโครงสร้าง** เพิ่มฟิลด์ได้เท่านั้นไม่ลบ; การลบฟิลด์ต้องผ่านหน้าต่าง deprecation 2 เวอร์ชันหลัก
- ACL สำหรับอินเทอร์เฟซ Pathfinder รักษาความสามารถในการแปลง **2 เวอร์ชันล่าสุด** เลือกโดยอัตโนมัติ
- หมายเลขเวอร์ชันเส้นทางภายในของ Booking (RouteVersion ภายใต้คำสั่งซื้อเดียวกัน) และหมายเลขเวอร์ชัน Event เป็นคนละมิติ ห้ามใช้ร่วมกัน

## ช่องว่างที่ทราบและข้อสันนิษฐาน (ความจริงใจภายใต้ข้อจำกัดของ blind run)

| รายการ | สถานะ | หมายเหตุ |
| :--- | :--- | :--- |
| ช่องทางการแจ้งเตือนลูกค้า (อีเมล/SMS/in-app) | ยังไม่รวมใน Context อย่างเป็นทางการ | .abstracted มาจาก `CustomerNotifiedOfReroute` ใน `02-discover` แต่ยังไม่แน่ว่ารุ่นนี้จะแยกเป็น Context อิสระหรือไม่; แนะนำให้เป็น output port ของ Tracking |
| Billing / CRM | ชัดเจนว่าไม่ใช่เป้าหมาย | ตัดออกแล้วใน `scope`; ถ้าในอนาคตเพิ่มเข้ามา ความสัมพันธ์กับ Booking ต้องสร้างแผนที่ใหม่ |
| การจัดตารางของบริษัทเรือ คลังสินค้า | ชัดเจนว่าไม่ใช่เป้าหมาย | เช่นเดียวกัน |
| ข้อมูลหลักของรหัสท่าเรือ | สันนิษฐานว่ามี "คลังคำศัพท์ท่าเรือภายใน" | ว่าจริงๆ แล้วควรแยกเป็น Context สนับสนุนหรือไม่ต้องยืนยัน |

## แผนภาพทิศทางการพึ่งพา (ฉบับข้อความ)

```text
Customer ──submit──▶ Booking ──query──▶ [ACL] ──────▶ Pathfinder (ภายนอก)
                       ▲                  │
                       │                  └── แปลง ──▶ RouteCandidate
                       │
                       │ สมัครรับ AcceptedHandlingEvent
                       │
                    Handling ◀──ลงทะเบียน── ผู้ปฏิบัติงานท่าเรือ / พันธมิตรภายนอก
                       │
                       │
                       ▼
                    Tracking ◀── สมัครรับ(Event ที่ Booking เผยแพร่) ── Booking
                       ▲
                       │
                    ลูกค้า (สอบถามด้วยตนเอง)
```
