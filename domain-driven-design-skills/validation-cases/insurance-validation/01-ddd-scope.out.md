# 01 — ผลผลิต ddd-scope (Blind Run)

> อินพุต: `00-fuzzy-prompt.md`
> ไฟล์นี้เป็นผลลัพธ์การจำลองการทำงานของ `ddd-scope` ใน blind run โดย**ไม่ได้อ้างอิง**วัสดุ ground truth (กรณีนี้ไม่มีการอ้างอิงการใช้งานจริง)

## ปัญหาและคุณค่า

- **ปัญหา**: ข้อมูลขาดความต่อเนื่องในกระบวนการรับประกันภัยและการเรียกร้องค่าสินไหมทดแทน — ผู้รับประกันภัยไม่เห็นประวัติผลงานการเรียกร้องค่าสินไหมทดแทนที่สมบูรณ์ พนักงานเรียกร้องค่าสินไหมทดแทนไม่ได้รับข้อมูลเงื่อนไขที่แม่นยำ ฝ่ายบริหารไม่สามารถติดตามขนาดเรียกร้องค่าสินไหมรอตัดบัญชีแบบเรียลไทม์ ส่งผลให้การตัดสินใจช้า ข้อผิดพลาดมาก และการส่งข้อมูลให้หน่วยงานกำกับดูแลเป็นไปอย่างล่าช้า
- **คุณค่า**: ผ่านฐานข้อมูล "ลูกค้า—กรมธรรม์—เรียกร้องค่าสินไหม" ที่เป็นหนึ่งเดียวและกระบวนการทั้งหมดเป็นดิจิทัล ทำให้การตัดสินใจรับประกันภัยมีหลักฐาน กระบวนการเรียกร้องค่าสินไหมทดแทนแม่นยำ เรียกร้องค่าสินไหมรอตัดบัญชีมองเห็นได้แบบเรียลไทม์ และปฏิบัติตามข้อกำหนดการส่งข้อมูลให้หน่วยงานกำกับดูแล

## เป้าหมาย / ไม่ใช่เป้าหมาย

**เป้าหมาย**:

- สร้างฐานข้อมูล "ลูกค้า—กรมธรรม์—เรียกร้องค่าสินไหม" ที่เป็นหนึ่งเดียว สามารถเชื่อมโยงอัตโนมัติข้ามกระบวนการ (แจ้งเหตุสามารถเชื่อมโยงกับกรมธรรม์ที่มีผลบังคับได้)
- สนับสนุนกระบวนการรับประกันภัยทั้งหมด (รับ / เพิ่มเบี้ย / จำกัดความรับผิดชอบ / ปฏิเสธ / ขอการประกันต่อ)
- สนับสนุนกระบวนการเรียกร้องค่าสินไหมทดแทนทั้งหมด (แจ้งเหตุ → ตรวจสอบ → ประเมินค่าเสียหาย → อนุมัติ → จ่าย → ไล่เบี้ย) รวมถึงการระงับการสอบสวนทุจริต
- ฝ่ายบริหารติดตามขนาดและการกระจาย "แจ้งเหตุแล้วยังไม่จ่ายค่าสินไหม" แบบเรียลไทม์ (มุมมองเงินสำรอง)
- ปฏิบัติตามข้อกำหนดการส่งข้อมูลให้หน่วยงานกำกับดูแลและการคำนวณเงินสำรองตามกฎหมาย

**ไม่ใช่เป้าหมาย**:

- การกำหนดอัตราเบี้ยประกัน: อัตราให้โดยระบบคณิตศาสตร์ประกันภัยภายนอก ระบบของเราใช้เฉพาะผลอัตราเท่านั้น (อธิบายขอบเขต: หลีกเลี่ยงการนำแบบจำลองคณิตศาสตร์ประกันภัยที่ซับซ้อนเข้ามาในขอบเขตการสร้างแบบจำลอง)
- การลงทุนและการใช้เงิน: การดำเนินงานทางการเงินอยู่ในระบบการเงินภายนอก (อธิบายขอบเขต: การจ่ายค่าสินไหมทดแทนทำเฉพาะคำสั่งและใบเสร็จเท่านั้น)
- ระบบฝั่งบริษัทนายหน้า: มีปฏิสัมพันธ์ผ่าน API ไม่สร้างแบบจำลองกระบวนการภายในของพวกเขา (อธิบายขอบเขต: หลีกเลี่ยงการขยายตัวของแบบจำลองข้ามองค์กร)
- กระบวนการประกันชีวิต/ประกันสุขภาพ: กรณีนี้มุ่งเน้นกระบวนการหลักการรับประกันภัยและการเรียกร้องค่าสินไหมทดแทนประกันทรัพย์สิน

## รายการเตรียมการขั้นตอนต่อไป

- **บทบาท**: ผู้รับประกันภัย พนักงานเรียกร้องค่าสินไหมทดแทน ฝ่ายบริการลูกค้า (รับแจ้งเหตุ) ฝ่ายการเงิน/การปฏิบัติตาม (อนุมัติและส่งข้อมูล) ฝ่ายปฏิบัติการ (จัดการภัยพิบัติและสถานการณ์ผิดปกติ)
- **อินพุตที่จำเป็น**: การยืนยันจุดกำกวมในรายการคำศัพท์จากบทบาทข้างต้น ตัวอย่างเงื่อนไขกรมธรรม์จริง (ตัวอย่างค่า deductible/ระยะเวลาคอย/ความรับผิดชอบที่ยกเว้น)
- ผลผลิตที่คาดหวัง: ตารางลำดับเหตุการณ์ (เส้นทางหลัก + ทางเลือกผิดปกติ) คำสั่ง/เหตุการณ์ผู้สมัคร รายการจุดร้อนและจุดกำกวม (`ddd-discover`)
