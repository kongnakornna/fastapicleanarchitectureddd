# เกณฑ์การให้คะแนน (Rubric) — กรณีตรวจสอบประกันภัยการรับประกันและการเรียกร้อง

> กรณีนี้เป็นกรณี**ที่ไม่มีข้อกำหนดอ้างอิง** (ขอบเขตไม่มีการอ้างอิง DDD จากโอเพนซอร์สที่ matures) การให้คะแนนใช้**ระบบการตรวจสอบโดยผู้เชี่ยวชาญ**: ไม่มีจุดอ้างอิง ground truth (จุดอ้างอิงประเภท A ต้องพึ่งพาการอ้างอิงการ implement ซึ่งไม่สามารถใช้ได้) แทนด้วยเกณฑ์สี่ประเภท ผู้ตรวจสอบตัดสินทีละรายการตามเนื้อหาของ artifact ผลการตัดสินแต่ละรายการต้องอ้างอิงรายการ artifact เฉพาะเป็นหลักฐาน

## 2. เกณฑ์การให้คะแนน (0–4 ห้าระดับ)

| ระดับ | ความหมาย                                |
| :--: | :---------------------------------- |
|  0   | ไม่มีผลลัพธ์                              |
|  1   | โครงสร้างผิด (ไม่ได้จัดเรียงตามข้อกำหนดผลลัพธ์ของ SKILL) |
|  2   | โครงสร้างถูกต้อง แต่ขาดแนวคิดที่สำคัญ              |
|  3   |命中แนวคิดหลัก มีข้อบกพร่องเล็กน้อยหรือเบี่ยงเบน      |
|  4   |命中เกณฑ์ทั้งสี่ประเภท และไม่มีการเบี่ยงเบนที่สำคัญ      |

## 3. เกณฑ์สี่ประเภท (แทนจุดอ้างอิง ground truth)

### A. ความสมบูรณ์ทางธุรกิจ

องค์ประกอบต่อไปนี้ใน brief ที่คลุมเครือ (`00-fuzzy-prompt.md`) ได้รับการครอบคลุมโดย artifact ทั้งหมดหรือไม่:

- บทบาท: ลูกค้า (บุคคล/องค์กร), นายหน้า, ผู้รับประกัน, ผู้ตรวจสอบ, เจ้าหน้าที่เรียกร้อง, ผู้อนุมัติ, การเงิน, ฝ่ายบริหาร, หน่วยงานกำกับดูแล
- กระบวนการ: การทำประกัน → การเสนอราคา → การรับประกัน → การออกกรมธรรม์ → การแก้ไข → การต่ออายุ/การระงับ → การแจ้งเรียกร้อง → การตรวจสอบ → การประเมินความเสียหาย → การอนุมัติ → การชำระเงิน → การเรียกคืน
- ข้อยกเว้น: ยอดภัยพิบัติรุนแรง, การเรียกร้องซ้ำ/เท็จ, เอกสารล่า, ข้อขัดแย้งจากการแก้ไขและการเรียกร้องพร้อมกัน, การตรวจสอบการฉ้อโกง, การชำระเงินล้มเหลว
- ข้อจำกัด: การรายงานต่อหน่วยงานกำกับดูแล, การอนุมัติหลายระดับ, ช่วงเวลาที่มีปริมาณงานสูงต้องไม่สูญเสียข้อมูล

### B. การปฏิบัติตามหลักการ DDD

- ขอบเขต Aggregate ยึดตาม Invariant, หนึ่งธุรกรรมหนึ่ง Aggregate; การอ้างอิงภายนอกมีการทบทวนวงจรชีวิตอีกครั้ง
- คำศัพท์มีความหมายเดียวภายใน Bounded Context; การใช้คำเดียวกันแต่ต่างความหมายข้าม Bounded Context ได้รับการแปล/เปลี่ยนชื่อแล้ว
- Event เป็นกาล past tense ไม่มีคำทางเทคนิค; Event ข้าม Bounded Context มี Idempotent key
- กฎทางธุรกิจแบบ predicate ถูกดึงออกมาเป็นอย่างชัดเจนเป็น Specification (ถ้ามี)

### C. ความสอดคล้องภายใน

- ผลลัพธ์ของแต่ละ Skill สามารถนำไปใช้ต่อในระยะถัดไปได้โดยตรง (ใช้หมายเลข/ชื่อ/คำศัพท์เดิม)
- Event ถูกนำเสนอใน discover, ถูกกำหนดอย่างเป็นทางการใน interactions, และถูกตรวจสอบใน review ลูกโซ่สมบูรณ์
- ความสัมพันธ์การอ้างอิงระหว่าง Bounded Context / Aggregate / Event ไม่มีความขัดแย้ง

### D. การระบุสิ่งที่เกินขอบเขตเชิงบวก

- การเสริมที่สมเหตุสมผลเกินความต้องการของ brief (เช่น รูปแบบการประมวลผลภัยพิบัติแบบ batch, Aggregate การเรียกร้อง, สายงานอนุมัติแบบ escalation)
- ไม่ถือว่าการ "เบี่ยงเบน" เป็นข้อผิดพลาด เว้นแต่ละเมิดเกณฑ์ A/B

## 4. กฎการให้คะแนน

- ระดับคะแนนแต่ละระดับต้องมีการอ้างอิงหลักฐาน (ไฟล์ artifact + บท/รายการ)
- **หลักการอนุรักษ์**: การตัดสินที่เกี่ยวข้องกับ "ยังไม่ได้รับการยืนยันจากฝ่ายธุรกิจ/ภายนอก" (เช่น การตัดสินใจเรื่องข้อคลุมเครือ, ทางเลือกอื่นสำหรับการแบ่งขอบเขต) คะแนนไม่เกิน 3
- คะแนนถ่วงน้ำหนักรวม = Σ(คะแนน × น้ำหนัก) / (4 × Σน้ำหนัก) × 100%
- คะแนนของระบบการให้คะแนนนี้**สะท้อนเฉพาะคุณภาพเปรียบเทียบตามมุมมองการตรวจสอบโดยผู้เชี่ยวชาญ** เทียบกับคะแนนที่มี ground truth ของกรณี Cargo ไม่สามารถเปรียบเทียบได้โดยตรง
