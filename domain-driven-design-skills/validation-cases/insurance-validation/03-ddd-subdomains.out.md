## คำแถลง Domain หลัก

- **Domain หลัก**: การตัดสินใจรับประกันภัย + การจัดการเรียกร้องค่าสินไหม (รวมเรียก "วงจรรับประกันภัย—เรียกร้องค่าสินไหม")
- **คุณค่า**: คุณภาพการรับประกันภัย (การเลือกความเสี่ยง) และคุณภาพเรียกร้องค่าสินไหม (การประเมินค่าเสียหายแม่นยำ ป้องกันทุจริต) เป็นคันโยกหลักสองประการของอัตราการจ่ายค่าสินไหมและผลกำไรของบริษัทประกันทรัพย์สิน ดิจิทัลทำให้ทั้งสองใช้ฐานข้อมูลเดียวกันและตอบสนองซึ่งกันและกัน (ประวัติเรียกร้องค่าสินไหม → การรับประกันภัย)
- **ขอบเขต**: การตัดสินใจรับประกันภัยใช้ "ประวัติเรียกร้องค่าสินไหมของลูกค้า + ใบเสนอราคา" ผลิตการตัดสินใจ การจัดการเรียกร้องค่าสินไหมใช้ "สแน็ปช็อตเงื่อนไขกรมธรรม์ + แจ้งเหตุ" ผลิตผลการจ่ายค่าสินไหมและคำสั่งจ่าย
- **ตัวชี้วัด**: อัตราการรับประกันภัยและสัดส่วนการเพิ่มเบี้ย อัตราการจ่ายค่าสินไหม วงจรเรียกร้องค่าสินไหม (จากแจ้งเหตุถึงจ่าย) อัตราการระบุทุจริต อัตราความคลาดเคลื่อนเรียกร้องค่าสินไหมรอตัดบัญชี
- **ความเสี่ยง**: กฎการตัดสินใจและกฎเรียกร้องค่าสินไหมกระจายวิวัฒนาการส่งผลให้ขอบเขตเลื่อน การตัดสินใจด้วยมือพึ่งพาประสบการณ์บุคคล ขยาย规模ได้ยาก
- **ทิศทางวิวัฒนาการ**: กฎอัตโนมัติ → แบบจำลองช่วยรับประกันภัย/ประเมินค่าเสียหาย ผลเรียกร้องค่าสินไหมตรวจสอบได้ เล่นย้อนหลังได้

## ผู้สมัครขอบเขต

- Subdomain → Bounded Context การเริ่มต้น:
  1. การจัดการลูกค้า主体 → Bounded Context `ลูกค้า主体`
  2. การรับประกันภัยและการเสนอราคา → Bounded Context `การรับประกันภัยเสนอราคา`
  3. การตัดสินใจรับประกันภัย → Bounded Context `การตัดสินใจรับประกันภัย`
  4. การจัดการกรมธรรม์ → Bounded Context `การจัดการกรมธรรม์`
  5. การรับแจ้งเหตุ + การจัดการเรียกร้องค่าสินไหม → Bounded Context `เรียกร้องค่าสินไหม` (รวม ดูเครื่องหมายขอบเขต)
  6. การดำเนินการจ่าย → Bounded Context `การจ่าย`
  7. การส่งข้อมูลกำกับดูแล + มุมมองเรียกร้องค่าสินไหมรอตัดบัญชี → Bounded Context `มุมมองกำกับดูแล`
- ผู้สมัครรวม: ขั้นตอนอนุมัติ (Generic) เป็นบริการแพลตฟอร์มที่เรียกร้องค่าสินไหมและการจ่ายใช้งาน ไม่แยกเป็นโดเมนอิสระ การไล่เบี้ยรวมเข้าการจัดการเรียกร้องค่าสินไหม (ขอบเขตความสอดคล้องเดียวกัน ต้องเชื่อมต่อกับการจ่ายเงินคืน)
