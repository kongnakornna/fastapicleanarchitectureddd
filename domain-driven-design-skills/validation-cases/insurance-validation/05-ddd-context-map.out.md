# 05 — ผลผลิต ddd-context-map (Blind Run)

> อินพุต: blind output จาก `01`~`04`
> ไฟล์นี้เป็นผลลัพธ์การจำลองการทำงานของ `ddd-context-map` ใน blind run โดย**ไม่ได้อ้างอิง**วัสดุ ground truth (กรณีนี้ไม่มีการอ้างอิงการใช้งานจริง)

## ตารางความสัมพันธ์ Bounded Context

| ต้นน้ำ → ปลายน้ำ                         | รูปแบบความสัมพันธ์                      | วิธีการเชื่อมต่อ                        | สัญญาการส่งข้อมูล                                                                  | ทิศทาง              |
| :----------------------------------------- | :--------------------------------------- | :--------------------------------------- | :---------------------------------------------------------------------------------- | :------------------ |
| Party → Quotation / Underwriting / Claim   | Customer-Supplier                        | สอบถามแบบ同步 (ประวัติเรียกร้องค่าสินไหม ข้อม主体) | สัญญาสอบถาม PartyProfile (อ่านอย่างเดียว)                                         | ทางเดียว (Party ต้นน้ำ) |
| Quotation → Underwriting                   | Customer-Supplier                        | เหตุการณ์แบบไม่同步                      | ApplicationSubmitted / QuotePresented                                               | ทางเดียว           |
| Underwriting → Policy                      | Customer-Supplier                        | เหตุการณ์แบบไม่同步                      | UnderwritingDecisionMade (รวมเงื่อนไข)                                             | ทางเดียว           |
| Policy → Claim                             | Open Host Service + Published Language   | เหตุการณ์แบบไม่同步 + สอบถามสแน็ปช็อต    | กลุ่ม PolicyEvent (PolicyIssued / EndorsementApplied / PolicyLapsed / TermsSnapshot) | ทางเดียว (Policy ต้นน้ำ) |
| Claim → Payment                            | Customer-Supplier                        | คำสั่งแบบไม่同步 + เหตุการณ์ใบเสร็จ      | PaymentInstruction (คีย์幂emsp;font) + PaymentExecuted                               | สองทาง (คำสั่ง/ใบเสร็จ) |
| Payment → Regulatory                       | Conformist (ต่อขอบเขตกำกับดูแล)         | ฉายภาพเหตุการณ์                          | PaymentExecuted                                                                     | ทางเดียว           |
| Policy / Claim → Regulatory                | Conformist                               | ฉายภาพเหตุการณ์                          | PolicyIssued / ClaimClosed / ข้อมูลอินพุต ReserveView                               | ทางเดียว           |
| Quotation → ระบบอัตราภายนอก              | ACL (ด้านตรงข้าม Conformist)            | สอบถาม/ตอบแบบ同步                       | OpenAPI อัตราภายนอก → QuoteTerms ภายใน                                            | ทางเดียว (ภายนอกต้นน้ำ) |
| Party → ระบบนายหน้า (ภายนอก)             | ACL                                      | sync/ไฟล์                                | ข้อความ主体นายหน้า → PartyProfile ภายใน                                           | สองทาง (แลกเปลี่ยนข้อมูล) |
| Payment → ระบบการเงินภายนอก              | ACL                                      | สอบถาม/ตอบแบบ同步                       | PaymentInstruction ภายใน → ข้อความการเงินภายนอก → ใบเสร็จ                        | สองทาง             |

## ตารางความเป็นเจ้าของสัญญา

| สัญญา                                        | เจ้าของ             | ผู้ใช้งาน                               | กระบวนการเปลี่ยนแปลง                           | กลยุทธ์เผยแพร่       |
| :------------------------------------------- | :------------------ | :-------------------------------------- | :----------------------------------------------- | :------------------- |
| สัญญาสอบถาม PartyProfile                    | ทีมข้อมูลลูกค้า     | Quotation / Underwriting / Claim        | ช่องข้อมูลเพิ่มได้เท่านั้นห้ามลบ; เปลี่ยนความหมายต้องตรวจสอบร่วมกัน 3 ฝ่าย | ความเข้ากันได้ย้อนหลังมาก่อน |
| ApplicationSubmitted / QuotePresented         | ทีมผลิตภัณฑ์ช่องทาง | Underwriting                            | เพิ่มช่องข้อมูลได้; ลบต้องมีหมายเลขเวอร์ชัน | ความเข้ากันได้ย้อนหลัง |
| UnderwritingDecisionMade                     | ทีมผลิตภัณฑ์รับประกันภัย | Policy                                  | เปลี่ยนประเภทการตัดสินใจต้องตรวจสอบ            | ประเภทแบบมีเวอร์ชัน   |
| กลุ่ม PolicyEvent (TermsSnapshot)             | ทีมบริการกรมธรรม์  | Claim / Regulatory                      | เปลี่ยนโครงสร้างสแน็ปช็อตส่งผลต่อการตัดสินใจเรียกร้องค่าสินไหม ต้องทีมเรียกร้องค่าสินไหมยืนยัน | แบบมีเวอร์ชัน + หน้าต่างเข้ากันได้ |
| PaymentInstruction / PaymentExecuted          | ทีมเทคโนโลยีการเงิน | Claim                                   | คีย์幂emsp;fontเปลี่ยนแปลงไม่ได้; ที่เหลือเข้ากันได้ย้อนหลัง | แบบมีเวอร์ชัน       |
| ข้อมูลอินพุตฉายภาพส่ง (PolicyIssued / ClaimClosed) | ทีมข้อมูลการปฏิบัติตาม | กำกับดูแล                              | เปลี่ยนขอบเขตโดยฝ่ายการปฏิบัติตามผลักดัน เหตุการณ์ธุรกิจไม่เปลี่ยน | เหตุการณ์เก็บไว้เดิม |

## การตัดสินใจแปล/ACL

### ACL-1: ระบบอัตราภายนอก → Quotation

- **อินพุต**: ผลอัตราภายนอก (รหัสประเภทประกัน ตารางอัตรา รหัสเงื่อนไขอาจไม่ตรงกับภายใน)
- **เอาต์พุต**: `QuoteTerms { premium, deductible, waitingPeriod, exclusions[] }` ภายใน
- **กฎ**:
  - ตารางแปลงรหัสประเภทประกันภายนอก ↔ ภายใน; รหัสที่ไม่รู้จักเข้าพื้นที่กักกันและแจ้งเตือน
  - จำนวนเงินเป็นหน่วยสตางค์ทั้งหมด (หลีกเลี่ยงทศนิยม); ระยะเวลาเป็น ISO date
  - อายุการใช้งานใบเสนอราคาสร้างภายใน (ภายนอกไม่ให้)
  - เวอร์ชันไม่เข้ากัน: ใช้อัตราที่แคชไว้; ไม่มีแคช "ใบเสนอราคาล่าช้า" (E2)

### ACL-2: ระบบนายหน้า → Party / Quotation

- **อินพุต**: ข้อความนายหน้า (ข้อม主体 ข้อมูลคำขอ ช่องข้อมูลตั้งชื่อต่างจากช่องทางตรง)
- **เอาต์พุต**: `PartyProfile` และ `Application` โครงสร้างมาตรฐานภายใน
- **กฎ**: 主体ซ้ำ (เลขบัตร + ชื่อ); ช่องข้อมูลคำขอเติมค่าเริ่มต้น เก็บเครื่องหมายช่องทาง

### ACL-3: ระบบการเงินภายนอก ← Payment

- **อินพุต**: `PaymentInstruction` ภายใน → ข้อความระบบการเงิน (บัญชีรับเงิน จำนวนเงิน สกุลเงิน)
- **เอาต์พุต**: ใบเสร็จระบบการเงิน → `PaymentExecuted` ภายใน
- **กฎ**: คีย์幂emsp;font (paymentId + claimId) ส่งผ่านเพื่อรับประกัน幂emsp;fontภายนอก จำแนกล้มเหลว (ลองใหม่ได้/ลองไม่ได้) กระทบยอดวันตัดรอบโดยทีมการเงินตรวจสอบ

## ล้มเหลวและการบรรเทา

| ลักษณะล้มเหลว                  | ผลกระทบ              | การตรวจจับ             | มาตรการบรรเทา                         | กลยุทธ์ชดเชย                      |
| :------------------------------- | :------------------- | :---------------------- | :------------------------------------- | :--------------------------------- |
| อัตราภายนอกหมดเวลา/5xx          | ใบเสนอราคาสร้างไม่ได้ | การตรวจสอบหมดเวลา     | ลดระดับอัตราแคช; ใบเสนอราคา "รอการยืนยัน" | ลองใหม่ใบเสนอราคาเมื่อกู้คืน     |
| รูปแบบข้อความนายหน้าเปลี่ยน     | การรับคำขอล้มเหลว   | การตรวจสอบอัตราล้มเหลว | ปรับ ACL ให้เข้ากับเวอร์ชัน; ข้อมูลที่ไม่รู้กักกัน | เติมด้วยมือ                        |
| คำสั่ง Payment สูญหาย             | การจ่ายค่าสินไหมล่าช้า | การตรวจสอบหมดเวลาคำสั่ง | คำสั่งเก็บถาวร + ส่งใหม่ (幂emsp;font)    | คีย์幂emsp;font ตัดซ้ำ              |
| จ่ายล้มเหลว (ลองใหม่ได้)         | เงินไม่เข้าบัญชี     | การจำแนกใบเสร็จ        | ลองใหม่อัตโนมัติ ≤3 ครั้ง              | เกินจำนวนส่งให้คนจัดการ          |
| จ่ายล้มเหลว (ลองไม่ได้)          | ต้องมีคนแทรกแซง     | การจำแนกใบเสร็จ        | ช่องทางจัดการด้วยมือ                   | ปิดคดีต้องจ่ายสำเร็จก่อน          |
| Policy เหตุการณ์ส่งล่าช้า          | เรียกร้องค่าสินไหมเชื่อมเงื่อนไขไม่ได้ | การตรวจสอบความล่าช้าส่ง | เล่นเหตุการณ์จาก bus; เรียกร้องค่าสินไหมรอสแน็ปช็อตเงื่อนไข | เติมสแน็ปช็อตแล้วดำเนินการต่อ    |
| พีคแจ้งเหตุจากภัยพิบัติ           | แจ้งเหตุค้าง積       | การตรวจสอบระดับคิว    | รับอัตโนมัติ รับก่อนเติมทีหลัง           | ห้ามสูญเสีย (คิวเก็บถาวร)          |
| ฉายภาพส่งล่าช้า                   | เวลาส่งข้อมูลไม่ครบ | งานกระทบยอด           | จัดตำแหน่งสแน็ปช็อตเวลาส่ง           | กลไกส่งย้อนหลัง                   |
| ข้อมูลหลัก Party ขัดแย้ง           | ผู้รับประกันภัยอ่านประวัติผิด | การตรวจสอบอัตราความขัดแย้ง | กระบวนการจัดการข้อมูลหลัก           | การไกล่เกลี่ยด้วยมือ              |

## กลยุทธ์เวอร์ชัน

- สัญญาเหตุการณ์ใช้หมายเลขเวอร์ชันโครงสร้างเดียวกัน ช่องข้อมูลเพิ่มได้เท่านั้นห้ามลบ การเปลี่ยนแปลงที่ทำลายต้องผ่านหน้าต่าง deprecation 2 เวอร์ชันใหญ่
- คีย์幂emsp;fontของ `PaymentInstruction` **เปลี่ยนแปลงไม่ได้** (เส้น底线ป้องกันจ่ายซ้ำ)
- เปลี่ยนโครงสร้าง `TermsSnapshot` ต้องทีม Claim ตรวจสอบ (ส่งผลต่อการคำนวณประเมินค่าเสียหาย)
- เหตุการณ์อินพุตฉายภาพส่งไม่อัปเดตเวอร์ชัน — เหตุการณ์ธุรกิจเก็บไว้เดิม ขอบเขตปรับที่ฝั่ง Regulatory
- ทดสอบสัญญา: ผู้ใช้แต่ละรายดูแลทดสอบสัญญาสำหรับสัญญาต้นน้ำ ต้นน้ำก่อนเผยแพร่รันทั้งหมด
