# DDD Scope

> 🌐 English version: [English](SKILL.en.md)

## สถานการณ์ที่ควรใช้

- คำอธิบายความต้องการคลุมเครือ ผู้มีส่วนได้ส่วนเสียต่างกันเข้าใจขอบเขตปัญหาไม่ตรงกัน
- โครงการใหม่ที่เริ่มต้นก่อน ต้องล็อคขอบเขตการ Modeling, ข้อจำกัด และความเสี่ยงหลัก
- เมื่อ Skill ถัดมารายงานว่า "คุณค่าทางธุรกิจไม่ชัดเจน" ให้ใช้เป็นเป้าหมายการย้อนกลับ

## ความต้องการ Input

- **จำเป็น**: เป้าหมายทางธุรกิจหรือคำอธิบายปัญหา (อนุญาตข้อความที่ไม่ได้จัดรูปแบบ: บทสนทนา, ข้อความจาก PRD, คำอธิบายจาก Work Order ก็ได้)
- **ไม่จำเป็น**: รูปแบบระบบปัจจุบัน, ผู้มีส่วนร่วมสำคัญ, การพึ่งพาจากภายนอก, ข้อจำกัดที่รู้อยู่แล้ว (เวลา/กฎระเบียบ/ประสิทธิภาพ/ทีม)

## ขั้นตอน

1. แยกเจตนาทางธุรกิจออกมา สร้าง **ปัญหาStatements** 1 ประโยค (อธิบายปัญหา) และ **ค่าStatements** 1 ประโยค (อธิบายผลลัพธ์ที่ต้องการ)
2. ระบุ **เป้าหมาย** และ **ไม่ใช่เป้าหมาย** สร้างขอบเขต - ประกาศอย่างชัดเจนว่า "ไม่ทำอะไร"
3. ระบุ **ข้อจำกัดและสมมติฐาน** แต่ละข้อมีเครื่องหมาย "ตรวจสอบได้/ตรวจสอบไม่ได้" และวิธีตรวจสอบ
4. สร้าง **รายการศัพท์บัญชี**: แยกคำนาม, คำกริยา, คำสถานะจากคำอธิบาย ระบุจุดคลุมเครือและสาขาที่เกี่ยวข้อง
5. ระบุ **รายการความเสี่ยง**: ครอบคลุมความเสี่ยงทางธุรกิจ, การเชื่อมต่อ, ความสอดคล้องของข้อมูล, การส่งมอบ ให้ข้อเสนอแนะในการบรรเทาเบื้องต้น
6. สร้าง **รายการเตรียมพร้อมขั้นตอนถัดไป**: ข้อมูลขั้นต่ำที่ต้องการเพื่อเข้าสู่ `ddd-discover`, บทบาทที่เกี่ยวข้อง และผลลัพธ์ที่คาดหวัง

## ผลลัพธ์

| ผลงาน                    | ข้อกำหนดโครงสร้าง                                     |
| :------------------------ | :------------------------------------------------------ |
| ปัญหาStatements & ค่าStatements | แต่ละ 1 ประโยค ได้รับการยอมรับจากฝ่ายธุรกิจ             |
| เป้าหมาย/ไม่ใช่เป้าหมาย | จัดรูปแบบเป็นรายการ แต่ละข้อมีคำอธิบายขอบเขต           |
| ข้อจำกัดและสมมติฐาน      | ตาราง: ข้อจำกัด/สมมติฐาน, ตรวจสอบได้, วิธีตรวจสอบ      |
| รายการศัพท์บัญชี          | ตาราง: ศัพท์, คำจำกัดความ, จุดคลุมเครือ, สาขาที่เกี่ยวข้อง |
| รายการความเสี่ยง          | ตาราง: ความเสี่ยง, ผลกระทบ, เงื่อนไขการเกิด, ข้อเสนอแนะ  |
| รายการเตรียมพร้อมขั้นตอนถัดไป | รายการ: บทบาท, Input ที่จำเป็น, ผลลัพธ์ที่คาดหวัง       |

## รายการตรวจสอบ

- [ ] เป้าหมายและไม่ใช่เป้าหมาย mutually exclusive และสามารถปฏิบัติได้
- [ ] ข้อจำกัดและสมมติฐานทั้งหมดมีวิธีตรวจสอบระบุไว้
- [ ] ศัพท์บัญชี ≥ 10 คำ จุดคลุมเครือระบุไว้แล้ว
- [ ] รายการความเสี่ยงครอบคลุมธุรกิจ/เชื่อมต่อ/สอดคล้อง/ส่งมอบ 4 ประเภท
- [ ] ปัญหาStatements และค่าStatements ไม่มีรายละเอียดทางเทคนิค

## การย้อนกลับ

Skill นี้เป็นจุดเริ่มต้นของระบบ ไม่ย้อนกลับเอง แต่ situations ต่อไปนี้จะถูก trigger ให้ย้อนกลับมาจาก downstream:

- `ddd-subdomains` ไม่สามารถแยกแยะ Domain หลักได้ → คุณค่าทางธุรกิจไม่ชัดเจน ต้องกลับมาเล็ง scope ใหม่
