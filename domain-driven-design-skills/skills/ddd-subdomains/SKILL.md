# DDD Subdomains

> 🌐 English version: [English](SKILL.en.md)

## สถานการณ์ที่ควรใช้

- การค้นพบ Domain เสร็จสมบูรณ์แล้ว (Event Stream และคำสั่ง/Event ที่เป็นไปได้พร้อมแล้ว) ต้องการแบ่ง Domain ออกเป็น Subdomain
- ต้องการตัดสินใจเชิงกลยุทธ์ว่า "อะไรคือความสามารถหลัก อะไรสามารถซื้อ/ใช้ซ้ำได้"
- `ddd-context-map` รายงาน "God Context" หรือการจำแนก Subdomain ผิด ให้ใช้เป็นเป้าหมายการย้อนกลับ

## ความต้องการ Input

- **จำเป็น**: Event Stream, คำสั่ง/Event ที่เป็นไปได้, เบาะแสขอบเขต (จาก `ddd-discover`)
- **ไม่จำเป็น**: รายการความสามารถหรือ Module ของระบบปัจจุบัน, สมมติฐานความแตกต่างทางธุรกิจ, คำอธิบายความได้เปรียบในการแข่งขัน (จาก `ddd-scope`)

## ขั้นตอน

1. **แยกชุดความสามารถ**: แยกความสามารถทางธุรกิจ (Capability) จาก Event Stream ลบซ้ำและรวมความสามารถที่มีความหมายเหมือนกัน
2. **ระบุคุณสมบัติ**: ระบุคุณค่าทางธุรกิจ, ความซับซ้อน, ความถี่ในการเปลี่ยนแปลง, ระดับการพึ่งพาภายนอก สำหรับแต่ละความสามารถ
3. **จำแนก**: จำแนกตามประเภท Subdomain ของ DDD — Core (ความแตกต่างหลัก), Supporting (จำเป็นแต่ไม่แตกต่าง), Generic (ทั่วไปใช้ซ้ำได้)
4. **คำประกาศ Domain หลัก**: สร้างเอกสารคำประกาศ Domain หลัก — ทำไมถึงเป็น Domain หลัก, ตัวชี้วัด, ทิศทางวิวัฒนาการระยะยาว
5. **ข้อเสนอแนะความเป็นเจ้าของ**: แนะนำความเป็นเจ้าของทีม ปรับทิศทางขอบตัวอักษรและขอบเขตความสอดคล้อง ระบุจุดทำงานร่วมกันระหว่างทีม
6. **สร้างตัวเลือกขอบเขต**: ให้ข้อเสนอแนะการจับคู่เบื้องต้นจาก Subdomain ไปยัง Context สำหรับ `ddd-contexts`

## ผลลัพธ์

| ผลงาน               | ข้อกำหนดโครงสร้าง                                                           |
| :------------------- | :---------------------------------------------------------------------------- |
| รายการความสามารถ   | ตาราง: ความสามารถ, คำอธิบาย, Event ที่เกี่ยวข้อง, ความสัมพันธ์上下游            |
| ตารางจำแนก Subdomain | ตาราง: ความสามารถ/กลุ่มความสามารถ, ประเภท Subdomain, เหตุผลการจำแนก, ข้อเสนอแนะการลงทุน |
| คำประกาศ Domain หลัก | ไม่เกิน 1 หน้า: คุณค่า, ขอบเขต, ตัวชี้วัด, ความเสี่ยง, ทิศทางวิวัฒนาการ       |
| ข้อเสนอแนะความเป็นเจ้าของ | ตาราง: ความสามารถ/Subdomain, ทีมที่แนะนำ, ฝ่ายที่พึ่งพา, วิธีทำงานร่วมกัน |
| ตัวเลือกขอบเขต      | รายการ: ข้อเสนอแนะการจับคู่เบื้องต้นจาก Subdomain ไปยัง Context            |

## รายการตรวจสอบ

- [ ] ทุกความสามารถมีเหตุผลการจำแนก ฝ่ายธุรกิจและฝ่ายเทคนิคยอมรับได้
- [ ] คำประกาศ Domain หลักมีตัวชี้วัดทางธุรกิจที่วัดได้
- [ ] ระบุจุดทำงานร่วมกันระหว่างทีมอย่างน้อย 3 จุดและให้ข้อเสนอแนะ
- [ ] จำนวน Core Subdomain ≤ 1/3 ของ Subdomain ทั้งหมด (Domain หลักไม่ควรมากเกินไป)
- [ ] ตัวเลือกขอบเขตสามารถนำไปใช้โดย `ddd-contexts` ได้โดยตรง

## การย้อนกลับ

- ไม่สามารถแยกแยะ Core และ Supporting (ทุกความสามารถดูสำคัญเท่ากัน) → ย้อนกลับไป `ddd-scope` คุณค่าทางธุรกิจต้องชี้แจงใหม่
- ถูก trigger ย้อนกลับโดย `ddd-context-map`: การพึ่งพาแบบวงจรหรือ "God Context" บ่งบอกว่าการแบ่ง Subdomain ผิด

## ตัวอย่าง

```text
@ddd-subdomains
จาก Event Stream และเบาะแสขอบเขตต่อไปนี้ ช่วยระบุ Subdomain และจำแนก:
[วาง Event Stream และเบาะแสขอบเขตจาก ddd-discover]
สร้าง รายการความสามารถ, ตารางจำแนก Subdomain, คำประกาศ Domain หลัก และข้อเสนอแนะความเป็นเจ้าของ
```
